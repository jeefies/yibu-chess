# 弈步 0.8.3 · 对弈后台极速复盘缓存

[APK 下载页面](https://github.com/well49112/yibu-chess/blob/apk-downloads/yibu-0.8.3-arm64.apk) · [朋友 PR #2](https://github.com/well49112/yibu-chess/pull/2)

在“对局设置”的后台搜索预算中选择“极速”（默认）或“深入”。极速档在对弈间隙持续缓存，以减少赛后重复等待。人类和 Maia 落子都不取消上一着后台分析；切页面、切后台、换局、改口令仍正常取消。

## 核实结果

0.8.2 的深度复盘、复评本步和新讲解实际请求 `profile=deep`、MultiPV=2，没有指定 depth 或 maxTimeMs；真实客户端 MockWebServer 请求测试已复核通过。

朋友公开服务端 UniChessServer 的配置为：lightning 目标深度 22、500ms 搜索预算、默认单候选；deep 深度上限 128、4000ms 搜索预算。截图所说的 deep 3 秒与当前公开源码不完全相同，可能是部署版本或实测搜索时间不同；生产服务访问返回 403，未验证部署配置。

另一个实际问题：服务端 analyze_move/evaluate 在没有明确传 depth 时会使用 STANDARD_DEPTH=128，未继承 profile 的 depth=22。若传入 limits 对象却只填 depth，路由又会默认 maxTimeMs=4000。因此客户端极速档同时明确发送 limits.depth=22 和 limits.maxTimeMs=500，保留 MultiPV=2 以提供第二候选和 !! 所需证据。它与服务端单候选的 0.6 秒测试仍有参数差异。

参考服务端提交 f1ec3b4 的 [档位配置](https://github.com/jeefies/UniChessServer/blob/f1ec3b4afe1814f66b31cfef89cf5205c28c0245/sf_analyzer.py#L167)、[参数解析](https://github.com/jeefies/UniChessServer/blob/f1ec3b4afe1814f66b31cfef89cf5205c28c0245/sf_analyzer.py#L501) 和 [接口 limits 默认值](https://github.com/jeefies/UniChessServer/blob/f1ec3b4afe1814f66b31cfef89cf5205c28c0245/sf_router.py#L93)。公开配置不代表当前生产部署；预算不承诺每个局面完成 22 层或手机在 0.5 秒显示结果。

## 整合与修正

- 合并 PR 的后台持续队列、模式设置和持久化，并保留 0.8.2 的完整分段计时、请求编号及导出。
- 后台缓存检查明确使用当前 Stockfish 版本；原 PR 的默认 17.1 检查会将 19 的结果一直判为缺失。
- 每步每模式在本次运行阶段最多尝试一次；不一致或短深度结果保存供手动重试，不进入无限请求循环。
- AI 完成走子与后台分析并发时，以最新状态合并，保留复盘、讲解与棋步；保存继续由串行事务处理。
- 记录实际分析模式，切到深入档会刷新极速缓存；较长预算结果与旧深度结果可复用。评级继续核对同深度、精确分值及服务端比较许可。
- 保留 Room 延迟打开的单例语义，测试显式清理数据库；isOpen=false 不再导致每次取实例都创建新数据库。
- 不将“目标22层”写成保证完成。未缓存的复盘和手动复评仍走深入档；旧棋谱可能仍需数秒。AI 的 1–2 秒模拟思考、手动关键点操作与音效保持现有行为。

同包名、同个人签名，versionCode 16，可覆盖安装保留棋谱、Elo、口令和设置。只有设置增加后台预算字段，棋谱新增可缺省的分析模式字段，不需要重建数据库。
